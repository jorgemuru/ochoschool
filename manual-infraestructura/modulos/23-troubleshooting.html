Diagnóstico y solución de problemas

Diagnosticar desde la capa más baja hacia la aplicación evita cambios al azar.

SíntomaComprobaciónCausa probable
No hay conectividadping, ip route, tracerouteRuta, VLAN, firewall o VPN
No resuelve nombresnslookup, resolvectlDNS incorrecto o registro ausente
LDAP fallanc 389, ldapsearchDNS, puerto, credenciales u hora
Oracle fallanc 1521, lsnrctlListener, servicio, ruta o datasource
WAR .failedserver.log y markerDependencia, XML, clase o configuración
HTTP 404deployments y context-rootWAR no desplegado o URL incorrecta
HTTP 401/403token, rol y filtroJWT ausente/expirado o permisos
HTTP 409cuerpo JSONRegla de negocio
FileUpload fallatmp, permisos, max-post-sizeLímite o archivo temporal

Kit de diagnóstico

ip address; ip route; resolvectl status
ping -c 4 192.168.80.10
nc -vz 192.168.90.10 1521
curl -v http://localhost:8080/ochoschool.website/
systemctl status wildfly
journalctl -u wildfly -n 200 --no-pager
tail -n 200 $WILDFLY_HOME/standalone/log/server.log
Método

Registrar hora, síntoma, alcance, cambio reciente, comando ejecutado y resultado. Una hipótesis debe poder confirmarse o descartarse.
